# 月之日 · Moonsun（零猜测区域环推理）

浏览器原生的 **Moonsun（月さん / Nikoli "Moon-or-Sun"）**：无构建步骤、无打包器，棋盘、区域粗边、
月牙与太阳、环线与线头全部由 `<canvas>` 现画（`index.html` + `js/render/board.js`），运行时不装任何包。
玩法是画**一条闭合的环**：盘面被粗线切成若干区域，环必须恰好穿过每个区域的边界两次；环走进哪个区域，
就把那个区域的符号全走到、另一个符号一格都不碰；沿环走一圈，区域必须月·日交替
（判据是 `js/engine/rules.js:66` 的 `checks()`，页面与闸都读它，谁都不另记一本账）。

出货的每一张盘先被**不含任何推理规则的逐格穷举计数器** `countSolutions()` 证明唯一解（判据 1），
再被**只用命名规则**的铅笔求解器 `solve()` 从空盘推满、0 次猜测（判据 2）。两条路不许复用代码——
`tools/engine-test.mjs` 的 A0 断言的是文件里的事实（谁 import 谁、正文里有没有对面的调用），不是注释里的承诺。
两件事在**官方 5×5 例题**上会合：计数器数出 1 解、铅笔 0 猜推满，而铅笔推出来的逐格等于 Nikoli 印着的那条
解答（A1 的三条对账）。所以「零猜测」是准入门槛，不是文案。提示走的是**同一个**铅笔，所以它只指格、不替你画。

规则来源（两家独立机构，逐字抄）、题面歧义的裁决、设计取舍，以及**哪些话没有被任何闸守住**，都在 `DESIGN.md`。
本文那几张表里的每一个数都是**本轮**（2026-10-03）在这台机器上跑出来的，rc 写进日志工件而不是管道尾巴；
凡是写着「实测」而没有任何命令去比对的，都单独列在**不承诺**里。

## 规则（八条文，逐条对应 `checks()` 返回的 code）

盘面是 `R×C` 的方格，被粗线切成若干**区域**，部分格里印着**月亮**或**太阳**。玩家不填数字，
而是在格子里摆**环线的形状**：一格带走两条线（直穿或拐角），或者被钉成「不在环上」，或者还没动过。

| code | 条文 | 违反时页面上那句话（`CLAUSE_TEXT`，逐字） |
| --- | --- | --- |
| `degree` | 每格两条线 | 环经过一格就带走两条线：这格引出的线不是 2 条。 |
| `asym` | 两头都要接上 | 两格相邻却只有一格朝对方引线，这一头没接上。 |
| `disjoint` | 一条不许分段 | 环分成了互不相连的几段，题目要求的是一整条。 |
| `edge` | 不许出盘 | 环线穿出了棋盘边界。 |
| `cross` | 每区穿两次 | 每个区域恰好被环穿过两次（穿过边界线，不是走进去）。 |
| `symbol` | 区域的符号 | 环进哪个区域，就把那个区域的符号全走到、另一个符号一格都不碰。 |
| `alternation` | 月日交替 | 沿环走一圈，区域必须月亮、太阳交替。 |
| `empty` | 空盘不算 | 还没有画出任何环线。 |

code、名字、句子三份清单都只有 `js/engine/rules.js` 里那一份（`CLAUSE_ORDER` / `CLAUSE_NAME` /
`CLAUSE_TEXT`）：侧栏的条款表是**渲染**它，不是抄它——`core` 腿逐条比对 `li` 的文本等于引擎自己格式化的
那一条，页面上不存在第二份文案。为什么这么挑：新增一条 `checks()` 却忘了配句子，会出现「盘上有红格、
面板里却没这条」，而少一行的面板看起来和满的一模一样。`tools/engine-test.mjs` 的 A3 从反方向收：
`note('code', …)` 里出现的每个 code 都必须有句子，`CLAUSE_TEXT` 里也不许有报不出来的死行。

**判定的先后是有讲究的**（`checks()` 在结构违规处提前收工）：一格只引出一条线时，红的是线头而不是
「这个区被穿了几次」——半条环上的穿越次数是没有意义的读数。所以 `checks()` 给每条结论标 `level`，
`Game.report()`（`js/ui/game.js:55`）在还有线头时只念线头。空盘同理：`empty` 与度数为 1 的格子是 warn，
开局那一帧不会闪一屏红，但**判胜只认 error 级为 0**。

## 玩法（页面上能按的东西）

- **选尺寸**：下拉三档 `5×5 入门` / `6×6 标准` / `7×7 进阶`（`js/engine/tiers.js` 的 `TIERS`），
  换档就清档开新局。被淘汰的档**不是"暂时没做"**：侧栏「尺寸菜单为什么只有这几档」印着量出来的理由
  （下面「难点」那节逐字贴了同样的两行）。
- **一格八档**：`没画 → 不在环上 → 竖穿 → 横穿 → 上右拐 → 右下拐 → 下左拐 → 左上拐 → 回到没画`
  （`js/ui/game.js:14` 的 `SHAPE_CYCLE`，侧栏图例逐档写出来）。左键前进一档、右键（或中键）倒退一档。
  「钉成不在环上」和「还没动过」对判胜同值（都没线经过），但对**玩家**不同：前者是你主动声明的结论，
  画面上是一个点，后者是空的——少了这一档，「擦掉」和「擦成留空」在盘上就长一个样。
- **键位**：`↑↓←→` 移光标（越界时回到第 1 格，这个读数被 `keys` 腿钉着）；`空格`/`Enter` 前进一档；
  `0`–`6` 直接点到某一档（`0`＝不在环上，`1`–`6`＝六种直/拐）；`Backspace`/`Delete` 擦回没画；
  `h` 提示 · `z` 撤销 · `c` 全清 · `n` 换一局。焦点坐在按钮/下拉框上时键盘**归控件**：
  不挡这一层的话，一次空格会既按下按钮又改盘面。
- **翻页要挡**：空格在 Blink 里的"翻页"是 **keypress** 阶段的默认动作，只在 `keydown` 上
  `preventDefault()` 挡不住（取证过程与读数见 `DESIGN.md` 的键盘那一节）。所以 `js/main.js` 两个阶段都听。
- **提示**：拿**同一个**铅笔（`js/engine/pencil.js`）在**你当前已写的状态**上找下一条被迫的结论，
  只说「第 R 行第 C 格：环一定（不）经过这一格」，不说「画成这个形状」——把形状替你画完就把推理收走了。
  铅笔推不动时它明说推不动，并且那句「这种局不该出现在出货里（判据 2）」是真红的：出货的每一张都必须推得满。
- **换一局**：默认 seed 是随机数，不是按日期算的——同一个 seed 必须永远画同一张盘，
  「今天的 seed」会让界面上印着的那串数字明天就对不上号。画不出合法盘就顺延下一个 seed，
  最多 `MAX_ATTEMPTS = 24` 次（`js/engine/generate.js:173`），状态行上 `seed … · N 试` 念的就是这个数。
- **冲突回显**：`report()` 指到的格子在盘上标红，还没接上的线头标一个淡紫的点。
  判胜只问 `Game.wonNow()` 一次并把结论写回 `game.status`（`js/main.js:178` 的 `afterMove()`）：状态行、
  存档里的 `won`、幕布、以及「赢了之后拒绝再落子」读的是同一个 status，否则会出现赢了却写着「还差线索」。
- **动效**：`动效 全 / 动效 简` 一个按钮，同时改 JS 标志与 `documentElement` 的 class——只改一边的话
  canvas 不抖了、按钮却还在缩。也读 `prefers-reduced-motion`。
- **存档**：`localStorage` 键 `moonsun.save.v1`，字段 `version / sizeKey / seed / st / cursor / moves /
  moveCount / elapsedMs / fingerprint / savedAt / won`。**不存盘面对**：seed → 盘是引擎里的决定论映射，
  把 49 个格子抄进存档只会多出一条「存档和引擎画的不是一张盘」的失败路径。恢复前用
  尺寸 + 区域编号 + 符号行算出的**指纹**对一次账，对不上就作废存档、开新局、并把这事说给玩家听。
  撤销栈整条存下来（只存笔迹不存栈，刷新之后「撤销」会把人钉在原地）；时钟也存（续局从 00:00 重数，
  等于一局两小时的棋界面只走了两秒）。
- **续局**：刷新或换 URL 形态后从存档接回同一盘。同文档里跳 `#hash` 不算重载（那是 same-document
  navigation，`timeOrigin` 与文档身份都不许变）——`nav` 那条对照腿专门盯这一点。

## 难点：这一局的「难」是被量出来的那一种

- **出题是构造式的，不是随机摆线索**：`js/engine/generate.js` 先随机自避走铺出一条合法闭合圈，
  **沿环序**把圈切成 R（偶数）段——段序就是环经过区域的次序，所以「月·日交替」在建盘那一刻就成立，
  不需要事后修；环外的格挂到相邻区域（它们碰不到穿越计数，区域仍然是环上的一段连续路）；
  符号取极大化：环经过的格写本区域的符号，环外的格写**相反**符号，于是玩家看到的每一条线索都是
  「这个区不能是另一边」的证据。
- **挖线索的判据是 forced 进度，不是解数**：每拿掉一条线索都要**同时**过两道判据（铅笔仍 0 猜推满、
  计数器仍说 1 解），两个都过才真拿掉。拿解数当尺子会把「证唯一」的代价付在搜索里——这条是本仓的立项
  判断，两种目标函数对照过，见 `DESIGN.md`。
- **出货前不可省的一刀**：挖完之后 `bd` 已经不是任何解的答案盘，所以把计数器那张（唯一解）覆盖回
  `answer`，再整盘 `satisfies()` 复核一次；`build()` 里 `counter stopped during dig` / `not unique` /
  `pencil stalls on the dug board` / `answer illegal` 四条都是退货原因。
- **铅笔只用叫得出名字的规则**，一共 13 条（句子逐字来自 `js/engine/pencil.js:15` 的 `RULE_TEXT`）：

| 规则 | 说的是（逐字） |
| --- | --- |
| `N0_有边即在环` | 有一条线连进这格，这格就在环上。 |
| `N1_符号定标` | 区域里一旦走到过某个符号，这个区域就是那个符号：同符号的格全要走，另一个符号一格都不碰。 |
| `N2_两越定边` | 一个区域已经穿够两条边界，它剩下的边界就都不许再穿。 |
| `N3_度数满` | 这格已经接了两条线，其余方向一律不能再接。 |
| `N4_唯一出路` | 已定的那条线只剩一个方向还能接，就把它钉上。 |
| `N5_度数缺口` | 在环上的格还差两条而只剩两个空方向 → 都接上；已确定不在环上的格一条线都不许接。 |
| `N7_房间必进` | 每个区域都要被穿两次；能穿的那条边界只剩一条时，必走它。 |
| `N8_不成小环` | 接上就会闭合成圈、而盘上还有没安排完的格或区域，这条线不能接。 |
| `N9_环序平衡` | 月亮区与太阳区沿环交替，数量各占一半；一侧已经凑满，剩下的区域就全是另一侧。 |
| `N11_房内路径` | 环在一个区域里是一整条路：两个穿越口是它的两端，必须走的格要能串成这条路。 |
| `N12_路径不达` | 区域内一条还活着的路线都经过不了的格，不在环上。 |
| `N13_路径必达` | 每条还活着的路线都绕不开的格，一定在环上。 |
| `N14_邻室交替` | 所有活路都紧跟着进入的同一个区域，取与本区相反的符号。 |

  一条规则要能被点名，才谈得上「推不出来时该怪谁」；反过来，**从不开火的规则是装饰**，
  A5 拿三档 × 12 张的全仓直方图钉它（本轮每条都至少开火一次，最少的 `N8_不成小环` 22 次）。
- **尺寸菜单是被判据 1 的预算决定的**。计数器一次穷举的节点预算是 2000000
  （`js/engine/rules.js:170` 的 `CAP_WORK`），挖线索一盘的总花费上限是 16000000
  （`js/engine/generate.js:19` 的 `DIG_WORK = CAP_WORK * 8`）。节点数是**确定性**的量（同一个 seed 换机器
  烧掉同样的节点），所以拿它当闸；ms 只卡上界与方向，因为那是机器速度。菜单里每档的读数：

| 菜单 | key | 尺寸 | 唯一性节点 med | 唯一性节点 p95 | 出题预算 |
| --- | --- | --- | --- | --- | --- |
| 5×5 入门 | `5x5` | 5×5 | 4490 | 22896 | 4000 ms |
| 6×6 标准 | `6x6` | 6×6 | 50000 | 187983 | 8000 ms |
| 7×7 进阶 | `7x7` | 7×7 | 125573 | 1801534 | 16000 ms |

  这张表由 `balance` 的 B5 在 15 张样本上逐档**重测成等式**（`tiers.js` 的 `work` 不等于本轮实测就红），
  又被 `doctest` 的 D1 逐格钉成「文档那行 == 代码现值」——两头咬，改生成器或改文案都会红。

- **再大就买不起，而且出局理由印在页面上**（逐字来自 `eliminatedLine()`，`core` 腿比对页面文本）：

> 8×8：单试 5 张出货 3 张 · 唯一性计数节点中位 1,101,971（预算 2,000,000 的 55%）· 最坏 1,379,562（69%）· 退货 not unique (6)／pencil stalls on the dug board · 点一次「换一局」要连着退货才拿得到一张盘，而每一张都是在浏览器主线程上跑一次两百万节点的穷举。
> 10×10：单试 5 张出货 5 张 · 唯一性计数节点中位 1,649,604（预算 2,000,000 的 82%）· 最坏 1,946,473（97%）· 无退货 · 出货率不是问题，问题是有一张已经贴到预算线上：再深一点计数器就只能返回「没证完」，而那句谎判据 1 不允许说。

  这两行的每一个数都由 B6 在**当前这棵树**上重新量一遍（`OVER_N` 固定 5，不跟着 `SAMPLES` 漂），
  理由变了红线才跟着变；页面那句是由这些字段**拼出来的**，所以一个没人验过的数字不可能只活在文案里。

## 破坏试验台账

台架是 `tools/sabotage.mjs`：一次只改一个真实字段，跑 `node tools/doctest.mjs`（打引擎的两把跑
`node tools/engine-test.mjs`），读回**真实 rc**，并且必须在日志里出现文档点名的那条 FAIL——只红在别处
不算逼到。复原只用内存里读回的原始字节 `writeFileSync`，绝不借 git 命令，复原后逐字节回读比对；
needle 在目标文件里必须恰好命中 1 次，对不上就判红不往下动。刀跑之前先跑**对照**：干净树上的
doctest 与 engine-test 都必须绿，否则"红了"说明不了是刀咬的。台账里的 rc 是从脚本读回来的真实读数，
"实跑"那一格与**三处**本轮「逼红 N · 未逼红 M」由台架自己钉回本文件（写法在 `tools/pin.mjs`）——
钉的是**行首锚点**而不是全局替换，因为全局替换曾经把下面那句**历史**读数也改成过本轮的数，
那时没有任何一条闸读得到它；现在 `D19` 拿合成台账现测这只手（少一处锚点、多一处无人认领、
历史那句被吞、台账行漂了，四种都必须红），钉对之后重跑不再改写。
定稿后整轮重跑：`逼红 26 · 未逼红 0`（`_tmp-moonsun-sab-final4.log`，跑在回填完这一版的文档之后；
这一份日志的末尾就是写者的自证读数「README 台账已经等于本轮读数（幂等：没有改写）」，跑完 `git status`
干净——幂等不必再靠另一个脚本重建 24 行喂回写者来证明）。

这台台架在仓里躺了很久，却没有任何调用方：`tools/verify.sh` 与 CI 都不跑它，`package.json` 里也没有

台账自己教的七件事（第一轮的读数在 `_tmp-moonsun-sab-r1.log`：那一轮 `逼红 19 · 未逼红 2`（刀 21 把），
没咬到的两把 K5/E2 都是**闸自己空转**，不是刀下得不对——这是这个台架最值钱的产出）：

- **K5 第一轮没红，因为名单改成手写之后 D3b 就空了。** `RULE_ORDER` 与 `RULE_TEXT` 是两条独立的声明，
  D3b 只在"剥掉注释后的正文"里数名字，于是这两份声明自己就把 13 个名字凑够了次数。修法是再剥两处声明
  （`dropDecl()`）并加一条 D3c「两处声明都被剥掉了」——剥不掉就说明这条又在空转。教训：一条数名字的断言，
  它的搜索空间必须**不含**它自己声明名字的地方。
- **E2 第一轮没红，因为 A3 从隔壁蹭到了句子。** A3 要在 `rules.js` 里比"报得出的 code"与"有句子的 code"，
  而它把 `CLAUSE_TEXT` 之后直到文件尾的整段都当成了文案区——`CLAUSE_NAME` 的键就住在那儿，
  删掉一句条文文案它照绿。修法：切到 `CLAUSE_TEXT` 那个块的 `\n};` 为止。
- **E1 之前是恒等式。** `RULE_ORDER` 一度写成 `Object.keys(RULE_TEXT)`，那 A0 的"两边同集合"永远为真，
  删一行规则文本它都不红。现在名单是手写的，两边各漂一半都会红——自我比较证明不了任何事。
- **台架也咬过自己一次。** 它把"实跑"那一格重写成 `|  K1 |`（多一个空格），而它自己的匹配只认 `| K1 |`，
  于是第二轮报"台账里没有 K1 这一行"退出。写者和读者对同一个形状各写了一份，就得让匹配宽松、
  重写出单一形状；并且这次让它**当场红**而不是静默跳过，否则"没人收这一轮的数"就又是一条空转。
- **写文档的那只手吞过历史。** 自钉的第一版对整个 README 做「那个格式」的全局 replace，于是台账里
  那句"第一轮的读数在 …r1.log：那一轮 19 红 2 未红"被一起改成了本轮的数——文档从此指着那份日志说一件
  日志里没有的事，而 D 系列没有任何一条读它（它不在任何等式的两边，只是散文）。现在钉的是**行首锚点**，
  锚点之外那一处必须点名自己所属的那一轮日志，否则 D19g 判它"无人认领"；D19 的七条合成用例里就有一条
  是"历史那句被改了一个字"，K21 再拿真 README 验一次这条真的会红。
- **对照组 N1 与反空转是同一件事的两面。** N1 插一句不承载数的纯散文，闸必须照绿；
  而 K11 打的是**接线本身**（`package.json` 的 `dev` 端口就是文档那句「本地 5276」的来源之一），
  它漂了而脚本没漂时，D7a 必须用「六个来源都解析到了」点名，而不是让正则扑空、静默变绿。
  D 系列每条等式都配这样一条反空转断言（解析到的条数 / 读到了那一行）——没有它们，
  「文档没写这一行」和「文档写的等于代码」在 rc 上长得一模一样。
- **刀切在 runner 自己身上时，不许动一个字节。** K22/K23 改的是 `tools/ci.sh`，而 `npm run ci` 正在
  边读边执行这一份文件：bash 读到哪算哪，长度一变，它没读到的那半截就从中间错位开始解析——红不是闸门红，
  绿也不是闸门绿。所以这两把都做成**同字节数、同行数**的原地替换（`.mjs`→`.bak`、`_RC=`→`_RX=`），
  台账那套"逐字节回读比对"照旧成立，而 runner 那份没读到的尾巴也不会错位。这条比"不许改行数"更紧：
  行数不动而字节数动了，一样会漂。

## 不承诺

完整清单在 `DESIGN.md` 的**不承诺**一节。要在这里重复的一句是：
所有 ms 都是本机读数，没有任何闸承诺某一档多少毫秒内出完题；
`7×7` 本轮 p95 `5289 ms` 是 `16000 ms` 预算的三分之一，慢机器上会怎样没有量过；
音效根本没有实现，因此也没有任何闸观察到一次发声；
13 条命名规则「每条都会开火」是在三档 × 12 张这批样本上量的，不是对任意盘的定理；
移动端只证到「几何没坏」，没有真机；立项阶段那两种挖线索目标函数的对照数
（按解数挖 vs 按 forced 挖）是写代码时的判断记录，本轮不复现。

## 上线的到底是哪一批文件

这个仓没有打包器：站点=一次文件拷贝。以前「拷哪些」写在 `pages.yml` 的 `run:` 里（手抄的几行
`cp`）。本地 `index.html` 直读仓库根，永远自洽；线上却按那份清单拷，于是页面后来引用的
`manifest.webmanifest`、`sw.js`、`icons/*` 可能一个都没上去——线上 404，而仓里的引擎测试与
真浏览器闸全绿，因为它们跑的都是仓库根，没有任何一步在「按清单拷」的那个环境下加载过页面。

现在清单只有一份，住在 `tools/assemble-site.sh`：CI 调它拷 `_site`，本地闸调它拷临时目录，
然后**对拷出来的产物**提要求（`tools/deploy-set.mjs`）：

- **W 清单与页面同源**：`pages.yml` 里必须真有 `run: bash tools/assemble-site.sh <dir>` 这一行，
  `ci.yml` 里必须真有 `run: node tools/deploy-set.mjs`。认的是调用那一行，不是文件里出现过这个
  路径——注释里本来就会写它，只 grep 字符串会被一句散文喂绿。
- **R 引用可达**：引用不靠手打名单。从 `index.html` 的 `href/src` 出发，凡解析出来是 `.js`/`.css`
  的就把那一站也扫一遍（CSS 的 `url()`、JS 去掉注释后的 `'./…'` 字面量、`new URL(x, base)` 的两种
  基、`navigator.serviceWorker.register`、`scope`），`manifest` 的 icons/screenshots/shortcuts 各自
  的 `src` 也算引用。取径上读不到的那一站本身就是红（读不到＝这一站根本没扫）。每条引用都必须在
  产物里且非 0 字节；绝对路径单列一条红，因为 Pages 挂在 `/<repo>/` 前缀下会跳出去。
- **P 位图不许说谎**：`manifest` 声明的 `sizes` 必须等于 PNG IHDR 的真实宽高。
- **钉住两个数**：R 段实际检查的路径条数（`29`）与这一次跑的断言条数（`47`），两个数
  都钉在 `tools/deploy-set.mjs` 顶部的那对常量里。没改页面却掉了，说明解析断了；删掉一张图标会同时
  少一条 R10 与那张的 P1/P2，所以两个数一起钉，断言条数能漂就是闸在缩水的信号。这一节故意只写数值、
  不写那对常量的名字：本仓原有的文档闸会拿"文档里出现过的同名标识号"回数它自己的条数（skyscraper
  的 D14b 就是这种钉法），两道闸共用一个名字就互相打红。

`tools/deploy-set-selftest.mjs` 是这两颗钉的阳性证明：它把仓库复制到临时目录，照着每一类断言
各下一刀（X1 清单不收位图目录 / X2 模块边改名 / X3 CSS 写绝对路径 / X4 `start_url` 绝对 /
X5 删光 >=512 图标 / X6 少一个必填字段 / X7 声明尺寸与真图不符 / X8 workflow 不调脚本 /
X9 CI 不跑闸 / X10 是阴性对照——往入口 JS 追加一行只写在注释里的假路径，闸必须仍然绿、条数仍然
`29`、断言仍然 `47`；X11 og:image 退回相对路径 / X12 og:image 的前缀指向别的 slug），
要求每一刀都让闸**点名**变红。靶子从 `DEPLOY_SET_DUMP=1`
的出处表现挑（取径真的会读的那支 JS / 那一张 CSS，不写死某一个仓的入口名），所以页面改了、仓与仓
不同，台架跟着走。

`node tools/deploy-set.mjs` 与 `node tools/deploy-set-selftest.mjs` 就是 CI 跑的那两条命令本身
（package.json 里的 `deploy-set` / `deploy-set:selftest` 只是同一支脚本的 npm 入口）；本仓的整闸在 `tools/verify.sh` 的 `=== deploy-set ===` 那一段也各跑一次。它们红的时候并进本仓那条出口的退出码——这一条是这么证的：
把 ci.yml 里那行 `run: node tools/deploy-set.mjs` 砍掉，本仓整闸必须点名红且退出码非 0。
所以「本地全绿、线上 404 自己的 manifest / sw.js / 图标」这一类坏法在本地就会红。
