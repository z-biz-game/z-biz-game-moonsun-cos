# 蛇莓 · Hebi-Ichigo（零猜测蛇形推理）

浏览器原生的 **Hebi-Ichigo / 蛇莓**：无构建步骤、无打包器，棋盘、箭头题面、蛇身配色全部由
`<canvas>` 现画（`index.html`，`js/render/board.js`），运行时不装任何包。
玩法是在白格里摆出若干条 `1→2→3→4→5` 的蛇：黑格里的**箭头 + 数字**写着「从这个黑格沿箭头方向
看过去，第一个遇到的数字必须是几」，蛇与蛇不能相邻（斜角可以），白格允许留空（`js/engine/hebi.js:16`）。

每一局在出货前都被**只用命名规则**的铅笔求解器从空盘推到底，再由不含任何推理规则的
**逐格穷举计数器** `countSolutions()` 证明唯一解：计数器一旦「数不完」（`bounded`）或与判据
不一致（`viol`），这张盘直接退货（`js/engine/generate.js` 的 `bounded` 与 `viol` 两处退货）。
所以「零猜测」是准入门槛，不是文案。提示走的是**同一个**求解器，因此它必须点名用了哪条规则、
落在哪一格（`tools/scenarios.js` 的 `hint` 场景）。

规则来源、设计取舍、以及**哪些话没有被任何闸守住**，都在 `DESIGN.md`。
本文下面那几张表里的每一个数都是**本轮**（2026-09-30）在这台机器上跑出来的，
凡是写着「实测」而没有任何命令去比对的，都单独列在**不承诺**里。

## 规则（四条文，逐条对应判据 `R1`–`R4`）

棋盘是 `R×C` 的方格，一部分格子是**黑格**：黑格里印着一个箭头（上/下/左/右）和一个数字 `0`–`5`，
这两个都是题面给的，玩家改不了。其余是**白格**，玩家往白格里写东西。

| 条文 | 说的是 | 代码里谁判它 |
| --- | --- | --- |
| **R1 蛇** | 白格里写的 `1(头)→2→3→4→5(尾)` 必须逐格共边连成一条，凑不满 5 格不算蛇；一个数字格只能属于一条蛇 | `js/engine/hebi.js` 的 `check()` 第一段（`walkHead` 走不满就报 `R1 … 连不满 5 格`，同一格被两条蛇走到就报 `R1 … 被两条蛇共用`） |
| **R2 邻** | 两条不同的蛇不能共边（斜着挨着可以） | 同函数第二段：两条蛇的格子共边就报 `R2 … 是两条蛇却共边` |
| **R3 眼** | 蛇头背对身体那一侧的延长线（也就是 `2→1` 方向再往前），到下一个黑格或盘边为止，不能看见别条蛇 | 同函数第三段：`eyeRay` 定方向，撞上别条蛇报 `R3 … 的眼看见了别的蛇` |
| **R4 读数** | 黑格的箭头方向上**第一个**遇到的数字必须等于黑格印的数；印 `0` 表示这条射线到下一个黑格/盘边为止一个数字都没有 | 同函数第四段：`ray()` 沿箭头走到黑格或边界为止，`got !== b.num` 就报 `R4 … 印的是 X，实际第一个数字是 Y` |

另外两句是判据形状的前提，也经常被玩家忽略：**题面不给蛇的条数**，也**不要求白格填满**——
留空是白格的合法状态（官方 5×5 例题 20 个白格里 10 个是空的）。
所以「剩下几格刚好还差 N 条蛇」这种**全局**计数在这类游戏里不成立，铅笔因此被明令禁止用它
（`js/engine/pencil.js` 的 `P0-区` 是它的局部版本）。

每条违反的字符串都以 `R1`–`R4` 开头（`js/engine/hebi.js` 的 `check`），因为「被自己那一条抓到」
本身就是断言的一部分：反例要求 R2 的红必须来自 R2，浏览器腿也断言屏幕上第一个词是条款号。

## 玩法（页面上能按的东西）

- **选档**：三档 `初 5×5 K=2` / `中 6×6 K=3` / `高 8×8 K=5`（`js/ui/game.js` 的 `TIERS`），
  点一张卡就出该局的一盘；`换一局` 只往前推种子游标，同一档的盘序列是可复跑的。
- **一格的三种状态**：数字 `1`–`5`、钉成的**留空**、以及既没写数字也没钉留空的**未定**。
  留空不是「擦掉」，它是你主动声明「这一格确定没有蛇」，胜负判定读的是这个区别。
- **指针**：一次点一个格把它选为光标，鼠标与触屏走同一条 `pointerdown` 路径（`js/main.js` 的
  `onPointerDown`）。点黑格不会改任何东西，只会回一句「是黑格：箭头与数字是题面印的，不能改」。
- **数字与留空**：侧栏 `空 / 1 / 2 / 3 / 4 / 5` 六个按钮，与键盘 `1`–`5`、`0` 或空格（钉留空）、
  `Backspace`/`Delete`（收回未定）走的是同一个 `write()`，因此没有第二条实现路径可以偷偷不一致。
- **方向键** `↑↓←→` 移动光标：跳过黑格，走到盘边就停住——把光标弹到对侧会让人以为按错了。
- **`h` 提示 / `z` 撤销**：提示是拿**同一个**铅笔在**你当前已写的状态**上再推一轮，
  第一条新结论连着它的规则名一起给你；如果推的过程撞上矛盾，它说的是「你写的数字和题面矛盾了」
  而不是替你改盘。命名规则推不出新一格时明说「剩下的要么靠你再看一眼题面，要么就是已经推完了」。
- **冲突回显**：判据抓到的格子在盘面上标出来。空盘不标——开局就闪一屏红只会让人以为题面坏了
  （这个宽容只给状态行和读数，**不给**胜负判定，见下条）。
- **胜利三条件缺一不可**：判据 0 条违反 / 每个白格都已定（数字或留空）/ 写下的数字与**唯一解**逐格相同。
  「填满但排错了顺序」不算赢，一个都赢不了（`js/ui/game.js` 的 `winFacts()`，浏览器 `win` 腿 24 条断言）。
- **纪录**：同档比较的顺序是先看**用了几次提示**，再看步数，最后看用时；
  撤销一步**不退还**提示计数——否则玩家可以靠撤销刷出一个「没求过提示」的纪录。
  这两句都是断言：`win` 腿往 `Store` 里灌三条对照局（慢而零提示、快而求过一次、同提示同步数但更快），
  看谁顶掉谁，再把结果读回选档页的纪录栏；`hint` 腿撤销掉提示落下的那一格之后，回读屏幕上的提示计数。
- **存档**：`localStorage` 键 `hebi-cos:v1` 里存的是（档位、种子、题面黑格、玩家写下的
  `R×C` 个字符的状态串——8×8 就是一串 64 个字符、已花的时间），**绝不存解**；
  每个字段都验过才敢信，脏字段退回「没有存档」而不是白屏。
  默认 seed 取自存自己的增游标，不取日期——否则界面上印着的 `seed 1234` 明天就对不上号了。
- **续局**：刷新或换 URL 形态后可以从「继续」卡片接回同一盘，计时从存档那一刻接着走；
  同文档里跳 `#hash` 不算重载（这条有 4 条断言专门盯 `timeOrigin` 与文档身份不许变）。

## 难点：这一局的「难」是被量出来的那一种

- **零猜测是准入门槛而不是形容词**：一张盘要出货，铅笔必须从空盘推满它，穷举计数器必须**恰好**
  数出一个解且不越界。唯一性计数本轮最大 10822 节点，预算 2000000 节点（`js/engine/generate.js`
  的 `opts.cap`）——前者必须小于后者，这句话现在是闸读的等式，不是散文。
- **难度只有一种说法：实测推理步数**。`difficulty() = stats.pencilSteps`，页面上每一档标的
  「实测 N 步」都是 `TIERS.med.steps`，而它由 `tools/balance.mjs` 的 `B5` 逐档对着重新测一遍。
- **铅笔只用叫得出名字的规则**，一共 10 条：
  `P4-零 P4-挡 P4-独 P4-尽 P1-链 P1-弧 P2-邻 P2-围 P3-眼 P0-区`
  （前缀 `P0`–`P4` 是规则族；`P4-*` 读黑格、`P1-*` 管链的接续、`P2-*` 管蛇与蛇的边界、
  `P3-眼` 管视线、`P0-区` 管连通块太小装不下一条蛇）。
  一条规则要能被点名，才谈得上「推不出来时该怪谁」。
- **为什么 8×8 是菜单顶端**：尺寸再大，铅笔会停在平台期——推不出新一格但盘没满，
  于是这张盘根本不出货。台架对 10×10 K=8 连试 6 次，本轮 `出货 0/6`（`tools/balance.mjs` 的观测段），
  所以 10×10 **故意不进菜单，而且出局理由印在选档页上**（`js/ui/game.js` 的 `OUT_OF_MENU.why`）。
- **挖线索的目标函数是推理进度，不是解数**：同一批 5×5 盘按「解数掉得最狠」挖，出货 2/60、
  每张要付 396 次穷尽计数；按「铅笔还能多钉几格」挖、推满之后只数一遍，出货 20/30、每张 19 ms。
  这两个对照数是写代码时的判断记录，本轮不复现（列在**不承诺**），但它们解释了为什么成本付在证明上
  是错的。

台账自己教的四件事：

- H11 是本轮补闸时顺手接上的旋钮——`ci.yml` 一直写着 `SAMPLES: "20"`，而 `balance.mjs` 只读
  `argv[2]`，所以那行 env 是**装饰**，文档里「`SAMPLES=20 npm run balance` 实测」那句说的是一个
  不存在的机制。接线补上之后，探针才拿得出「× 3 张」这个证人。
- H4 一开始是**假绿**：`D2b` 原来数的是整份 `pencil.js`，而 `P0-区` 在注释里就出现三次
  （文件头两条 + 实现上方一条），正文里只有一次（`js/engine/pencil.js:135` 的提示文案）。
  于是"每条规则名都不只活在注释里"这句标签在它自己的刀下兑现不了——把正文那一次改名，
  整份文件仍数到三次，闸照绿。改成剥掉注释行再数正文之后，十条名字在正文里各出现 ≥1 次，
  H4 才真的会红。
- H13 打的不是文档，是**闸的入口**：`tools/verify.sh` 的 `LEGS` 只认七个腿名，认不出的过去直接
  跳过——`LEGS=hint`（`hint` 是 `play` 腿里的一条 scenario，不是腿名）一声不响地跑出
  `=== ALL GREEN ===`，而一份报告都没有。补上 `*)` 分支之后这一枪必须以「未知的腿」点名变红。
- H13 顺手咬出了**补闸代码自己的 bug**：第一次跑这枪时 `rc=1` 却报「没有点名行」——
  `echo "…$leg（…）"` 在没有 `LANG` 的环境里把全角括号的首字节算进了变量名，
  于是 shell 吐的是 `leg: unbound variable`。红是红了，但它没点出是哪个腿名，
  这正是"红必须点名"要防的那类事。改成 `${leg}（` 之后这枪才拿到 `RED 未知的腿：hint`。


## 不承诺

完整清单在 `DESIGN.md` 的**不承诺**一节。要在这里重复的一句是：
所有 ms 都是本机读数，没有任何闸承诺某一档多少毫秒内推完；
音效没有任何闸观察到一次发声；10 条铅笔规则是否每条都会开火没量过；
`generate.js` 头部注释里的历史对照数（`2/60`、`396 次计数 ≈ 19 s`、`20/30 · 19 ms`）是写代码时的
判断记录，本轮不复现；移动端只证到「几何没坏」，没有真机。
